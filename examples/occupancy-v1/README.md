# L3 Furniture Group v1

独立于 L1/L2 的家具组团与空闲区域标注。仅在 Image 配置 `occupancyV1="true"` 时启用；模板由指定的正式 L2 项目控件生成，不删除或改名上游控件。

## 标注流程

1. 选择 Focus 功能分区。可点击“定位父分区”；操作只移动视图。
2. 创建家具组团，选择类型，用“画矩形 / 画多边形”绘制实际障碍占地。
3. 点“绘制预览”，确认父边界裁剪和同组并集，再应用。继续添加分块可给同组增加不连通的占地。
4. “生成剩余空间”仅处理当前父分区；候选是未分类，不自动认定可通行。
5. 在“组团与空闲区域”中选择可通行或受限空闲。混合区域使用“局部改为…”后绘制修正范围。
6. 完整覆盖且无冲突后，在“复核与问题”中明确确认父分区。最后由标注者自行提交。

没有家具的父分区仍需执行补余、分类和确认。卫生间沿用整室 L2，淋浴地面不会仅因用途被自动归入家具占用。通行宽度无未标定的实际尺寸阈值。

### 选中与调整（2026-08-26 UI fix1）

单个手工分块或待应用轮廓选中后直接显示原生编辑控件，矩形可用 8 个缩放点和整体拖动调整。多分块组团在右侧 Regions 中选择“编辑分块”；不会把多个分块的外包框当作组团占地。新矩形在预览裁剪/并集未改变轮廓时保持 Rectangle，已有多边形不做自动类型迁移。带孔洞的存储拆分和自动补余不开放内部顶点编辑。

右侧仅保留一套 L3 Rectangle、三点 Rectangle、Polygon 工具，L2/L1 参考的绘制工具不显示。已有参考数据和项目控件定义保持不变。

### 父边界与吸附（2026-08-26 snap fix1）

新绘制、待应用和已应用的手工轮廓都受所属 L2 父分区约束。已有对象从 `occupancy_context.parent_zone_id` 查找父分区，切换 Focus 不改变归属；只有新轮廓使用当前 Focus。矩形整体拖动保持尺寸和角度，缩放保持未移动边，越界时限制到有效位置；多边形顶点/连边不能穿出凹父分区。已不存在的父分区必须先重新绑定，不能偷用当前 Focus。

顶部“边界吸附”“原图像素吸附”默认开启，可分别关闭；关闭吸附不关闭边界限制。约 10 屏幕像素内优先吸附到真实父边线/顶点，保留父参考的浮点坐标，其余位置按原图像素对齐。缩放和平移不改变原图像素尺度；不是图像边缘识别，也不会自动识别家具轮廓。拖动反馈在原有状态行显示，不改变工具条高度。

旧草稿中已经越界的轮廓不在加载时自动修剪：可明确移回父分区，或继续使用“绘制预览”查看并确认裁剪；原先合法的轮廓不能继续拖出边界。自动补余与内部存储拆分仍使用局部修正，不开放内部顶点。修改后仍需按原有规则预览、复核和保存。

## 几何和身份

- `occupancy_rectangle` / `occupancy_polygon` 与 `occupancy_type` 按物理区域 ID 配对。
- `meta.occupancy_context.logical_id` 表示逻辑区域；家具的 `group_id` 稳定，同组可有多个不连通分块。
- Boolean 运算使用 polygon-clipping 0.15.7；孔洞通过 earcut 2.2.4 拆为不重叠的普通 Polygon。拆分后校验 XOR 与内部交叠，不允许用包围盒/凸包/填洞替代。
- 画布和右侧列表按逻辑区域显示。只有真正的组件边界显示；内部存储三角边隐藏。
- `source_version` 记录生成/接受参考时的来源快照；`parent_fingerprint` 检查具体父分区的几何、类别和父房间。因此无关父分区变化不会让本区失效。任务整体最新参考版本另由安全保存/提交接口检查。
- 前后端以同一规范化 SHA-256 格式计算指纹。指纹小数归一化不更改原始坐标。面积容差 `1e-8` 为图片百分比坐标的数值误差容差，不是面积过滤阈值。
- 后端 Shapely 2.1.2 独立验证几何并集、差集、交集，不仅比较面积总和。

## 保存与参考同步

批量/破坏性操作依次：保存当前草稿 → 下载完整恢复 JSON → 重新读取来源状态 → 检查预览指纹 → 一次撤销事务 → 再保存。前置失败不写入；后置保存失败保留本地数据并明确提示。

下载的恢复文件应保留；若浏览器拦截连续下载，请允许本地站点下载，或使用“更多 / 备份”手动保存。JSON 导出含全部参考、人工结果、Relations、来源与复核元数据；MultiPolygon 导出按逻辑区域组织。

`function_zone_to_occupancy` + `apply_policy=manual` 不由后台 worker 应用。用户显式应用参考时只替换引用快照，保持 L3 原样；已提交标注不改写。已删除/拆分/合并的父分区由用户明确重绑。跨参考版本应用是服务器基线切换，会重建编辑历史；操作前恢复文件及服务器审计可用于恢复。

## 创建与部署

```text
python manage.py create_occupancy_project --source-task <id> --source-annotation <formal-id> --title L3_FurnitureGroup_v1 --confirm-create
```

命令拒绝同名重复项目，不创建人工 L3 标注或草稿。使用明确指定的正式 Annotation，不根据图片名猜测来源，不读取上游草稿。

部署前执行迁移 `tasks.0062_reference_sync_profiles`。web 与 reference worker 必须一起升级；旧 worker 不识别新的手动策略，不能与已启用的 L3 mapping 同时运行。现有映射默认仍为 Room → FunctionZone 自动策略。
